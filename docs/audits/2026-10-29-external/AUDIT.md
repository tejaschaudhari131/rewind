## A. Authority, state transitions and semantic contracts

### A1 — P1: movement does not invalidate pending authorization

`evaluate_stationarity` sets `MOVING` without incrementing the scene version or invalidating the active observation. `begin_checkpoint_observation` accepts every prior state, and `commit_gate_decision` does not require `CHECKING` or a still-stable scene. The gate supplies a constant motion score of `0.12`, not a temporal measurement. `hands_clear=True` is also unconditional. The reproduced motion score of 100 followed by acceptance demonstrates the missing invalidation, not a hypothetical thread race. [backend/app/state_machine.py:127–156](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/state_machine.py#L127-L156) [backend/app/state_machine.py:185–239](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/state_machine.py#L185-L239) [backend/app/gate.py:317–325](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/gate.py#L317-L325) [backend/app/geometry.py:304–315](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/geometry.py#L304-L315)

**Fix:** make the session controller the only state writer. A detected movement, tracking loss, correction, camera shift, new plan, mode change or reset must invalidate the pending token and clear green state. Require a measured stability interval, valid registration and observed hand clearance before capture. At commit require the exact active token, current `CHECKING` state, unexpired deadline, and the current step's complete mandatory predicate set. Unknown hand clearance or hidden seating is not a pass.

### A2 — P1: reset permits a stale result to be published as current

The final compare-and-mutate in `commit_gate_decision` is synchronous. **Within one asyncio event loop there is no await between its comparison and mutation**, so adding a lock only inside that function does not address the actual failure. Two concurrent checks overwrite `active_observation_id`; the earlier result usually fails CAS, as reproduced. That exception is not handled by the endpoint and becomes an error rather than an orderly stale result. [backend/app/state_machine.py:203–239](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/state_machine.py#L203-L239) [backend/app/main.py:451–462](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/main.py#L451-L462)

Reset replaces the global `session_sm`, while the pending gate retains the old object. It can validly commit against that abandoned object and the endpoint broadcasts its result after reset. The new and old sessions reuse a fixed UUID. `App.tsx` accepts whichever request finishes and does not compare a reset generation. The reproduced result did **not** mutate the new object; it produced a stale accepted response/event that a client can display as current. [backend/app/main.py:123–127](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/main.py#L123-L127) [backend/app/main.py:288–296](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/main.py#L288-L296) [backend/app/main.py:451–462](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/main.py#L451-L462) [backend/app/state_machine.py:90–103](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/state_machine.py#L90-L103) [frontend/src/App.tsx:162–180](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/frontend/src/App.tsx#L162-L180)

**Concrete controller change:**

1. Keep a stable controller object per session, with a random session ID, monotonically changing generation, and an `asyncio.Lock` for one-process deployment.
2. Under that lock validate the transition and capture an immutable token containing session/generation, scene/plan/step/observation IDs, image hash, reference/calibration/policy IDs **and hashes**, and deadline. Do not read mutable `sm.part_id` after provider awaits.
3. Release the lock during provider work. Providers return evidence only; they cannot mutate the session.
4. Reacquire the lock; compare the complete token, current stability, deadline, and evidence. Commit once, or return a non-authorizing stale/unknown result. Remove `active_observation_id or env_obs`; missing active capture must reject.
5. Reset increments the generation under the same controller lock. Publish events with generation and monotonically ordered sequence numbers. Frontend ignores old generations and old observation results; aborting a fetch alone does not cancel backend authority.
6. For multiple workers, put CAS and event publication in a database transaction/outbox. A Python lock cannot coordinate process-local global sessions.

## B. Calibration, geometry and CAD

### B1 — P1: claimed calibration and holdout evidence are fabricated

`compute_planar_calibration` detects tags in the input image and fits a homography directly; it never undistorts the raw image. `build_calibration_envelope` then invents `fx=fy=0.9*image_width`, supplies zero distortion, generates a holdout UUID, and derives “holdout 95% error” from fitting residuals. A fit residual on the same 16 corners is not a held-out metric accuracy test. The metadata labels these raw pixels undistorted and can mark calibration validated. [backend/app/calibration.py:91–166](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/calibration.py#L91-L166) [backend/app/calibration.py:229–276](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/calibration.py#L229-L276)

If the golden reference corner file is missing, registration silently falls back to the current image's fit error. A moved camera can still fit its new mat perfectly, so this cannot detect a bump. If the file exists, a real camera is compared to synthetic golden pixel locations, rather than its own registered session reference. Missing reference masks similarly fall back to the current silhouette itself. [backend/app/calibration.py:152–166](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/calibration.py#L152-L166) [backend/app/geometry.py:223–227](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/geometry.py#L223-L227)

**Fix:** calibrate camera intrinsics/distortion for the actual resolution and camera settings; undistort once; estimate world pose from the known tag board; freeze a real session registration reference. Persist an independent holdout dataset and report its measured error. Missing calibration/reference means unknown, not a self-reference fallback. Validate homography rank/conditioning, finite values, pose orientation, usable image area and registration drift. Do not synthesize evidence IDs for absent captures.

### B2 — P1: top-of-part parallax exceeds the claimed ±0.25 mm accuracy

The scanner warps to `mat_z0`, measures visible top-face boundaries, and records the supplied 4 mm thickness without compensating the measurement plane. It hard-codes contact confirmed and 0.25 mm uncertainty. [backend/app/calibration.py:185–215](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/calibration.py#L185-L215) [backend/app/geometry.py:428–436](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/geometry.py#L428-L436) [backend/app/geometry.py:534–552](https://github.com/tejaschaudhari131/rewind/blob/bc7cd2b04425220965bc732b8b80ce54da450375/backend/app/geometry.py#L534-L552)

For a camera 500 mm above the mat, a feature at height 4 mm is magnified when mapped onto z=0. For a 150 mm feature:

```text
L_mat_estimate = L_true * Z / (Z - h)
               = 150 * 500 / 496 = 151.209677 mm
error          = 1.209677 mm = 0.806452% of the true length
L_true         = L_mat_estimate * (Z - h) / Z
               = L_mat_estimate * 0.992
```

That scalar case is useful for explanation, but implementation should use the actual calibrated pose. With world-to-camera convention `Xc = R Xw + t`, for world plane `Z=h`:

```text
H_h = K_undistorted [ r1  r2  (t + h*r3) ]
[X,Y,1]^T ~ inverse(H_h) [u_undistorted,v_undistorted,1]^T
```

Equivalent ray intersection, used in `recommended_primitives.py`:

```text
C = -R^T t
d = R^T [x_normalized, y_normalized, 1]^T
lambda = (h - C_z) / d_z
X_world = C + lambda*d
```

First obtain normalized rays with `cv2.undistortPoints(raw_pixels, K_raw, distortion)`. Reject parallel rays, intersections behind the camera, invalid pose and unknown feature height. Use the real `h` for the observed edge: a top rim, bottom bore edge and sidewall silhouette do not all lie in one plane. If the link is tilted or raised, a single constant-height correction is insufficient. OpenCV explains the calibrated plane/pose relationship in its [homography tutorial](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html).

**The formula removes modeled parallax; it does not guarantee ±0.25 mm.** At this geometry, a 1 mm height error alone contributes about 0.30 mm length error. A hard-coded `uncertainty_95_mm` is untenable. Establish a budget for print scale, intrinsic calibration, pose, height/contact, edge localization and repeatability; validate independent physical lengths and hole centers across the scan area, rotations and lighting. Inflate uncertainty or refuse CAD eligibility when the bound is exceeded. Upsampling to 4 px/mm does not create source-image information.

The supplied helper recovers synthetic distorted, tilted-camera points with maximum coordinate error below `4e-12 mm`; this checks algebra only, not webcam accuracy.

### B4 — P1/P2: fixture-shaped heuristics do not establish physical seating or precision
